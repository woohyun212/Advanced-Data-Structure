# 1. 프로젝트 개요

본 과제는 C 언어로 구현된 텍스트 기반 RPG “텍스트 디아블로(Text Diablo)”를 완성하는 것을 목표로 한다.  
교수님이 제공한 원본 코드는 Act 1 전체와 Act 2 일부까지만 구현되어 있었으며, 이후 Act 2의 나머지 퀘스트와 Act 3, Act 4는 퀘스트 함수 골격만 존재하는 상태였다.

본 구현에서는 다음을 수행하였다.

- Act 2의 Q2_4, Q2_5, Q2_6 퀘스트 및 보스 전투 구현
- Act 3의 Q3_1 ~ Q3_6 전체 퀘스트 및 보스 전투(메피스토) 구현
- Act 4의 Q4_1 ~ Q4_3 전체 퀘스트 및 최종 보스(디아블로) 전투 구현
- 퀘스트 데이터(.dat) 파일과 C 코드 간의 매핑 구조를 재정비하여, 데이터 기반으로 퀘스트를 관리할 수 있도록 개선

게임은 총 4개의 Act로 구성되며, 각 Act는 여러 개의 퀘스트(Quest1_1 ~ Quest4_3)로 세분화된다. 플레이어는 텍스트로 출력되는 스토리와 전투 메뉴를 통해 캐릭터를 조작하며, 전투를 통해 경험치와 골드를 획득하고, 레벨업 및 아이템 사용을 통해 성장해 나간다.  
각 Act의 마지막 퀘스트는 보스 전투로 구성되어 있으며, Act 3의 메피스토(MEPHISTO), Act 4의 디아블로(DIABLO / DIABLO[각성])가 주요 보스로 등장한다.

# 2. 개발 환경

- 사용 언어
  - C 언어 (C99 표준)
- 컴파일러 및 빌드 옵션
  - Makefile 상의 기본 설정
    - `CC = gcc`
    - `CFLAGS := -x c -std=c99 -Wall`
    - `LDFLAGS :=` (별도 링크 옵션 없음)
- 플랫폼 지원 구조
  - 코드 상단에서 OS에 따라 다른 헤더를 포함하도록 구성
    - Windows: `#include <conio.h>`, `#include <windows.h>`
    - POSIX 계열(Linux, macOS): `#include <unistd.h>`, `#include <termios.h>`, `#include <fcntl.h>`
  - `getch()`, `kbhit()`, `clrscr()`, `gotoxy()`, `textcolor()` 등 콘솔 제어 함수는  
    Windows와 비 Windows 환경 모두에서 동작하도록 조건부 컴파일 및 별도 구현을 사용
- 개발/테스트 환경
  - 코드 및 Makefile에 특정 OS/컴파일러 “버전”은 명시되어 있지 않으며,  
    본 README에서는 일반적인 gcc/clang 계열 컴파일러가 설치된 Windows / Linux / macOS 환경을 기준으로 빌드 방법을 설명한다.

# 3. 빌드 및 실행 방법

## 3.1 공통 사항

- 소스 파일: `Diablo-m-test.c`
- 기본 실행 파일 이름: `Diablo-m-run` (Windows에서는 `Diablo-m-run.exe`로 실행)
- 제공된 `Makefile`을 이용할 수도 있고, 단일 소스 파일을 직접 컴파일해도 된다.

---

## 3.2 Windows (gcc / MinGW 기준)

### (1) 직접 컴파일

MinGW-w64 또는 유사한 gcc 환경에서:

```bash
gcc -std=c99 -Wall -o Diablo-m-run.exe Diablo-m-test.c
Diablo-m-run.exe
```

PowerShell 기준:

```powershell
gcc -std=c99 -Wall -o Diablo-m-run.exe Diablo-m-test.c
.\Diablo-m-run.exe
```

### (2) Makefile 사용

```powershell
# 빌드
make          # 또는 mingw32-make 등 환경에 맞는 make 명령

# 실행
.\Diablo-m-run.exe

# 정리 및 재빌드
make clean
make          # 또는 make clean_build
```

> `Makefile`에서 기본 `TARGET`은 `Diablo-m-run`으로 정의되어 있으며,  
> Windows에서는 실행 시 `.exe` 확장자가 붙는다.

## 3.3 Linux

### (1) 직접 컴파일

```bash
gcc -std=c99 -Wall -o Diablo-m Diablo-m-test.c
./Diablo-m
```

### (2) Makefile 사용

`Makefile`은 OS를 감지하여 Linux인 경우 별도의 타깃 이름을 사용하도록 설정되어 있다.

```bash
# 빌드
make          # HOST_OS=Linux 인 경우 TARGET=MAKEPIC 으로 설정됨

# 실행
./MAKEPIC     # 또는 Makefile에 설정된 TARGET 이름

# 정리 및 재빌드
make clean
make          # 또는 make clean_build
```

> 실제 제출/실행 시에는 `TARGET` 이름을 `Diablo-m-run`으로 맞추거나,  
> README에 명시된 실행 파일 이름을 기준으로 조정하면 된다.

# 4. 구현 내용 정리

## 4.1 전체 구조 및 원본 대비 핵심 변화

### (1) 퀘스트 함수 골격 → 실제 구현

- 원본 코드에서 Act 2~4의 퀘스트 함수는 모두 다음과 같은 더미 구현 상태였다.
  - `Q2_4() { return; }`, `Q3_1() { return; }`, `Q4_3() { return; }` 등
- 완성본 코드에서는 각 함수에 스토리 진행, 몬스터 등장, 보스 전투, 보상 지급, 퀘스트 진행도 갱신 로직을 모두 구현하였다.
- 전투는 공통 함수 `set()`을 통해 수행되며, 각 퀘스트는 `set_monster()`로 몬스터를 설정한 뒤 `set()`을 반복 호출하여 전투를 진행한다.
- 사용자 상태는 `struct my_sturct`(`user`)와 `struct monster_struct`(`monster`)를 통해 관리한다.
  - `user` 구조체: `name`, `lv`, `hp / nhp`, `mp / nmp`, `attack`, `defence`, `gold`, `exp`, `item[8]`, `wh`(퀘스트 진행도) 등
  - `monster` 구조체: `name`, `lv`, `hp / nhp`, `mp / nmp`, `attack`, `defence`, `gold`, `exp` 등

### (2) 퀘스트 선택/매핑 로직 개선

- 원본 코드
  - 퀘스트 선택 시, 퀘스트 번호 `l`에 대해
    - `if (l==1) fp24=fopen("Quest1_1.dat","rt");`
    - `...`
    - `if (l==21) fp24=fopen("Quest4_3.dat","rt");`
  - 퀘스트 실행도
    - `if (l==1) Q1_1();`
    - `...`
    - `if (l==21) Q4_3();`
  - 즉, 파일명과 함수명을 모두 긴 `if` 체인으로 관리하여 유지보수가 어려웠음.
- 완성본 코드
  - 다음과 같은 구조체와 테이블을 도입:
    ```c++
    typedef struct {
    const char *file_name;
    void (*func_name)(void);
    } QuestInfo;

    static const QuestInfo quest_map[] = {
    {NULL, NULL},
    {"QUEST1_1.DAT", Q1_1},
    ...
    {"QUEST4_3.DAT", Q4_3},
    };
    ```
  - `get_quest_info(int quest_id)` 함수로 퀘스트 정보를 조회해,
    - `.dat` 파일명과 퀘스트 함수 포인터를 동시에 얻고,
    - 유효성 검사 후 `quest->func_name();` 으로 퀘스트를 실행
  - 이를 통해 퀘스트 추가/수정 시 한 곳(테이블)에서 관리할 수 있도록 구조를 개선하였다.

### (3) 전투(set) 및 입력 처리 개선

- `set()` 함수
  - 원본: `void set()`
  - 완성본: `int set()`
    - 전투의 결과(성공/도망/중단 등)를 호출 측에서 판단할 수 있도록, 반환값을 갖는 형태로 변경
    - 각 퀘스트 함수에서는 `if (set() == 0) return;` 형태로,  
      플레이어가 도망가거나 전투가 중단된 경우 퀘스트 진행을 적절히 중단하도록 처리
  - 레벨업 처리 시 `user.exp <= 0` 조건을 검사하여 레벨을 올리고, 체력/마나/공격력 증가를 직업(`cs`)에 따라 다르게 적용
  - `l_m` 변수를 사용해 남은 몬스터 수(Leave Monster) 를 관리, 전투 UI에 표시
- 전투 메뉴
  - `1. Melee Attack`, `2. Magic`, `3. Eat potion`, `4. Run Away` 네 가지 선택지를 제공
  - `Run_away()` 기능이 새로 구현되어, 전투 도중 도망가는 로직을 지원
- 입력 처리
  - 원본에서 `scanf("%d", &input);` 형태로 직접 입력을 받던 부분을,
  - 완성본에서 `scani()`라는 래퍼 함수를 사용하여 잘못된 입력에 대한 방어 코드를 강화
  - 개발 메모에 기록된 Issue #34 (Potion 잘못된 번호 입력 시 몬스터에게 데미지) 등을 해결하면서,  
    전체적으로 입력값 검증 및 에러 처리 로직이 보강된 형태이다.

## 4.2 Act 2 – Q2_4, Q2_5, Q2_6

### Q2_4 – 패스트푸드 테마 던전 및 롯데리우스 전

- 원본 상태
  - `Q2_4() { return; }` 만 존재하는 완전 더미 함수.
- 구현 내용
  - 입장 조건: `user.lv >= 25` 인 경우
    - “레벨이 높아 더 이상 출입 불가능” 메시지를 출력하고 퀘스트를 종료.
  - `l_m = 13;`으로 설정하여, 남은 몬스터 수를 13마리로 초기화.
  - 반복문을 통해 `"고지방 감자튀김"` 등 중간 몬스터들을 `set_monster()`로 설정 후 `set()`을 호출하여 전투 진행.
  - 전투가 정상적으로 모두 끝난 경우, 보스 NPC “롯데리우스”와의 대사 출력 후
    - `set_monster("롯데리우스", ...)` 호출로 보스 전투를 진행.
  - 전투 승리 시:
    - 플레이어에게 `Super Healing Potion`을 보상으로 지급 (`user.item[2] += 1`).
    - 퀘스트 진행도(`user.wh`)가 10이라면 11로 증가.
- 데이터 구조 사용
  - `set_monster()`는 몬스터의 레벨, HP/MP 범위, 공격력 범위, 방어력, 골드/경험치 범위를 인자로 받아,
    - `monster` 구조체의 각 필드를 난수 기반으로 초기화한다.
  - `l_m`를 통해 잔여 몬스터 수를 관리하여, 전투 UI에 남은 적 수를 표시함으로써 던전 클리어 진행 상황을 표현한다.

### Q2_5 – 하수구 던전 전투 (냉장고 듀리엘 전 준비)

- 원본 상태
  - `Q2_5() { return; }`
- 구현 내용
  - 입장 조건: `user.lv >= 26` 인 경우 입장을 제한.
  - `l_m = 14;`로 초기화하고, `"치어 좀비"` 등 수중/하수구 분위기의 몬스터들을 순차적으로 배치.
  - 각 몬스터에 대해 `set_monster()` + `set()`을 호출하며, 전투 결과에 따라 퀘스트를 계속/중단.
  - 마지막에는 보스 “냉장고 듀리엘”을 등장시키고, 이후 스토리상 Act 2 보스 전으로 자연스럽게 연결된다.
- 데이터 구조 사용
  - 몬스터 스펙은 난수 범위를 포함하는 파라미터로 관리하여, 동일 퀘스트를 반복하더라도 다소 다른 전투 경험을 제공.
  - `user.wh`를 통해 Act 2의 스토리 흐름을 제어하며, 해당 퀘스트를 클리어해야만 다음 퀘스트로 진행 가능하게 설계.

### Q2_6 – 냉장고 듀리엘 보스 전

- 원본 상태
  - `Q2_6() { return; }`
- 구현 내용
  - 입장 조건과 기본 구조는 Q2_5와 유사하게 구성되며, Act 2의 실질적인 보스 전투를 담당.
  - `l_m = 12;`로 설정하여 소수의 강력한 몬스터 웨이브를 배치하고,
    - `"Frozen Stew Chunk"` 등 냉기/냉장 테마의 몬스터들로 파티를 구성.
  - 마지막에 다시 `"냉장고 듀리엘"`을 `set_monster()`로 설정하고 보스 전투를 수행.
  - 승리 시:
    - `Great Healing Potion`, `Great Mana Potion`을 각각 1개씩 지급 (`user.item[4]`, `user.item[5]` 증가).
    - `user.wh == 12`일 때 13으로 증가시켜, Act 2의 보스 퀘스트가 완료되었음을 표현.

## 4.3 Act 3 – Q3_1 ~ Q3_6 (회 센터 / 수산 시장 테마 + 메피스토 전)

Act 3는 전반적으로 수산/회/해산물 테마의 몬스터와 스토리로 구성되어 있으며, 마지막 Q3_6에서 보스 메피스토(MEPHISTO)와의 전투가 진행된다.

### Q3_1 – 초반 몬스터 웨이브

- `l_m = 5;`로 설정하여 비교적 짧은 웨이브를 구성.
- `"Ink_Rebel"`, `"Salted_Veteran"`, `"Sashimi_Berserker"`, `"Boiled_Enforcer"`, `"King_Squid"` 등  
  다양한 해산물/회 단어를 패러디한 몬스터들을 차례로 등장시킨다.
- 각 몬스터는 `set_monster()`로 세팅 후 `set()` 호출을 통해 개별 전투를 수행.
- 클리어 시 `user.wh == 13` → 14로 증가.

### Q3_2 – 갑각류/정치 패러디 몬스터 웨이브

- `l_m = 6;`
- `"Crab_Militia"`, `"Shell_Guardian"`, `"Tax_Collector"`, `"Claw_Senator"`, `"Republic_Hammer"`, `"President_Gestin"` 등  
  갑각류와 정치/행정 요소를 섞은 몬스터들을 등장시킨다.
- 마지막 `"President_Gestin"`은 중간 보스급 몬스터에 해당하며, 스펙이 다른 몬스터보다 높게 설정되어 있다.
- 클리어 시 `user.wh == 14` → 15.

### Q3_3 – 주방/셰프 테마 던전

- `l_m = 3;`로 비교적 짧은 웨이브.
- `"Demonic_LineCook"`, `"Sous_Chef"`, `"Sashimi_Wraith"` 등을 맞이한 뒤,
  - 화면을 지우고 셰프 마고로시와의 대사를 출력.
- 이후 `"Chef_Magoroshi"`를 보스로 `set_monster()` 한 뒤 전투를 진행.
- 클리어 시 `user.wh == 15` → 16.

### Q3_4 – 거대 해양 생명체 웨이브

- `l_m = 3;`
- `"Rotwave_Whale"`, `"Sonic_Leviathan"`, `"Blood_Whale"` 등의 거대 해양 몬스터를 연속적으로 배치.
- Act 3 후반부를 위한 난이도 조정 구간이며, 체력과 공격력 수치가 전반적으로 높게 설정되어 있다.
- 클리어 시 `user.wh == 16` → 17.

### Q3_5 – 낚시/혼령 테마 및 조낚귀 전

- `l_m = 3;`
- `"Hooked_Spirit"`, `"Line_Binder"`, `"Soul_Net"` 등 낚시줄/혼령을 모티브로 한 몬스터들을 배치.
- 이후 `"조낚귀(JoNakGwi)"` 등장 전 대사를 출력하고, 보스 몬스터로 설정 후 전투를 수행.
- 클리어 시 `user.wh == 17` → 18.

### Q3_6 – 메피스토 보스 전

- 입장 조건: `user.wh > 18`인 경우, 한 번 이상 클리어한 뒤에는 재도전을 막기 위한 경고 메시지를 출력하고 종료.
- 클리어 전에는 메피스토와의 대사(플레이어 이름 포함)를 단계적으로 출력하며,  
  `textcolor()`와 `delay()`를 사용해 연출을 추가.
- 이후 `l_m = 0;` 설정 후,  
  `set_monster("MEPHISTO", user.lv + 8, ...)` 호출로 플레이어 레벨 기반 보스 스펙을 설정하고 전투를 수행.
- 승리 시 `user.wh == 18` → 19로 증가, Act 3 보스 퀘스트 완료.

## 4.4 Act 4 – Q4_1 ~ Q4_3 (악마 공무원 & 최종 보스 디아블로)

### Q4_1 – 악마 공무원 웨이브

- `l_m = 5;`
- `"악마 공무원"` 몬스터를 5회 반복해서 등장시키는 구조.
- 종국적으로 최종 보스를 향해 가는 과정에서 난이도를 끌어올리는 역할.
- 클리어 시 `user.wh == 19` → 20.

### Q4_2 – 곽팀장 전

- `l_m = 3;`
- `"악마 공무원"`을 3회의 웨이브로 등장시킨 뒤,
- `"곽팀장"`을 보스 몬스터로 설정하여 전투를 진행한다.
- 클리어 시 `user.wh == 20` → 21.

### Q4_3 – 최종 보스 디아블로 (2페이즈 전투)

- 입장 제한: `user.wh > 21`이면
  - “보스급 스테이지는 한 번 이상 클리어가 불가능”하다는 메시지를 출력하고 재도전을 막음.

  - 플레이어와 디아블로의 대사를 번갈아 출력하며 최종 전투의 분위기를 조성.
  - `textcolor()`와 `delay()`를 통해 강조 및 연출 구현.
- 전투 1페이즈:
  - `l_m = 0;`
  - `set_monster("DIABLO", 35, ...);` 로 1페이즈 디아블로를 생성.
  - `set()`을 호출하여 1차 전투 수행.
- 2페이즈 전환:
  - `monster.nhp < 1` 조건에서 추가 연출을 출력한 뒤,
  - `set_monster("DIABLO[각성]", 35, ...);` 호출로 강화된 2페이즈 보스를 생성.
- 승리 시:
  - 최종 스토리를 마무리하는 대사를 출력.
  - `user.wh == 21` → 22로 증가, 게임 전체 메인 퀘스트가 사실상 완료된 상태가 됨.

# 6. 문제 해결 과정

본 과제 진행 중 기록된 “개발 메모”를 바탕으로, 주요 이슈와 해결 과정을 요약하면 다음과 같다.

## 6.1 전투/진행 관련 이슈

### Issue #26 – `Play_1()` 무한 재귀

- 증상
  - `Play_1()` 함수가 자기 자신을 계속 재귀 호출하는 구조로 작성되어 있어,  
    게임 진행 중 특정 조건에서 무한 재귀 → 스택 오버플로우가 발생.
- 해결
  - 재귀 구조를 반복(루프) 기반 흐름으로 재구성하여,  
    함수 호출 깊이가 계속 쌓이지 않도록 수정.
  - 해당 수정은 PR `#38 [Fix] issue#26 무한 재귀 해결`에 반영.

### Issue #31 / PR #45 – `Run_away()` (도망가기) 기능 미구현

- 증상
  - 전투 메뉴에 도망 기능이 필요하지만, 실제 `Run_away()` 함수와 관련 로직이 미구현.
  - 플레이어가 불리한 전투를 회피할 수 없어 게임 플레이 상 선택지가 부족.
- 해결
  - `Run_away()` 함수를 새로 구현하고,
  - 전투 루프(`set()` 함수 내 스위치문)에서 `4. Run Away` 선택 시 해당 함수를 호출하도록 연결.
  - 도망 성공/실패 여부에 따라 `set()`의 반환값을 적절히 조정하여,  
    퀘스트 함수들이 도망 상황을 감지하고 흐름을 제어할 수 있도록 함.

### Issue #27 / #28 – `Battle()` 텍스트 출력 및 딜레이 최적화

- 증상
  - `Battle()` 함수 내에서 텍스트 출력 시 사용하는 `delay()` 처리와 범위 검증(`l` 변수 등)이 비효율적이거나 잘못되어,
    - 출력 속도가 지나치게 느리거나,
    - 특정 상황에서 비정상 동작(스크롤 깨짐 등)이 발생.
- 해결
  - PR `#64 [Fix] #27 #28 issue 해결; Battle() 함수 수정`에서
    - 딜레이 값과 루프 조건을 조정하여 불필요한 대기 시간을 줄이고,
    - 범위 검증 로직을 명확하게 정리하여 출력 안정성을 확보.

## 6.2 아이템/입력 처리 관련 이슈

### Issue #29 – `Potion()` 물약 능력 분리 오류

- 증상
  - `Potion()` 함수에서 각 물약이 회복해야 할 HP/MP 유형이 명확히 분리되지 않았거나,  
    잘못된 인덱스 처리로 인해 의도하지 않은 회복 효과가 발생.
- 해결
  - 물약별로 회복 대상(HP/MP) 및 수치를 분리하고,
  - 배열 인덱스 접근 시 철저히 범위를 확인하도록 로직을 수정.

### Issue #34 / PR #40 – 잘못된 포션 번호 입력 시 몬스터에게 데미지

- 증상
  - `Potion()` 호출 시 존재하지 않는 번호(예: 11)를 입력하면,
    - 에러 메시지가 출력되어야 하지만,
    - 실제로는 몬스터에게 데미지가 들어가는 비정상 동작이 발생.
- 해결
  - 입력값 검증 로직을 보강하고,
  - 잘못된 번호 입력 시 아무런 전투/데미지 연산을 수행하지 않도록 수정.
  - 관련 수정은 `PR #40 – [Fix] #34 Potion() 잘못된 번호 입력 시 몬스터 데미지 방지`에 반영.

### 입력 처리 전반 – `scani()` 도입

- 배경
  - 원본 코드에서는 `scanf("%d", &변수);` 형태의 직접 입력이 많아,
    - 잘못된 입력(문자 입력, 범위를 벗어난 값 등)에 대한 방어가 부족.
- 개선
  - `scani()`라는 정수 입력 전용 래퍼 함수를 도입하여,
    - 버퍼 비움, 예외 처리 등 공통 입력 검사를 중앙집중적으로 수행.
  - 퀘스트 선택, 전투 명령 선택 등 핵심 입력 부분을 `scani()`로 교체하여 안정성을 높였다.

## 6.3 UI/상태창 관련 이슈

### Issue #32 – Condition 창에서 바로 못 나감
